# 非遗智能定制模块设计方案

最后更新：2026-02-09

## 1. 模块概述

非遗智能定制模块用于让用户通过“提示词（prompt）”与“参考图（可选）”生成定制设计效果图，并在前端展示与保存生成记录，形成“从灵感到成品”的闭环。

模块核心目标：
- 支持 **仅提示词生成**（文生图）
- 支持 **提示词 + 参考图生成**（图生图）
- 支持生成记录查询与复用（便于用户二次迭代 prompt）
- 支持并发与限流控制（避免腾讯侧并发限制导致失败）

与现有系统的衔接：
- 前端入口：`/customize`（已实现交互与历史记录）
- 鉴权：用户需登录（沿用现有 `requiresAuth`）
- 文件上传：图生图接口直接接收 `multipart/form-data`，后端保存参考图到 `uploads/ai-ref` 并拼接可访问 URL（依赖 `file.public-base-url` 配置）

## 2. 需求分析

### 2.1 功能需求

1. **输入方式**
   - 必填：prompt（提示词）
   - 可选：参考图（单张图片）

2. **参数控制（MVP 先做通用参数）**
   - 分辨率：`resolution`（如 `1024:1024`）
   - 随机种子：`seed`（可选）
   - 风格：`style`（可选）
   - 强度：`strength`（仅图生图可选，范围 `0~1`）
   - 生成数量：`count`（图生图使用，建议限制 `1~4`）

3. **生成流程**
   - 用户提交参数后，后端调用腾讯混元生图能力
   - 当前实现为同步接口（后端内部轮询任务直至完成），返回结果图片 URL（`resultImage`/`resultImages`）
   - 前端展示生成结果（预览/下载），并刷新历史记录

4. **记录管理**
   - 用户可查看自己的生成记录（分页）
   - 记录包含：id、prompt、参考图 URL（可为空）、结果图 URL

### 2.2 非功能需求

1. **可靠性**
   - 腾讯接口失败需返回明确错误信息（并记录到任务表）
   - 对大文件、非法参数进行校验与提示

2. **性能与并发**
   - 限制单用户并发提交（如同一时间最多 1~3 个任务）
   - 支持总并发上限（避免触发腾讯侧并发限制）

3. **安全**
   - 仅登录用户可调用
   - 防止 prompt 注入导致日志污染或系统异常（做长度限制与必要的过滤）

## 3. 总体方案与关键决策

### 3.1 为什么推荐 COS（或对象存储）承载参考图/结果图

- 参考图如果走 Base64，容易触发请求体过大与内存开销
- 结果图如果只使用腾讯返回的临时 URL，存在过期或不可控风险
- 对象存储 URL 可长期稳定访问，便于生成记录长期保存

开发策略建议：
- 开发期：可先使用本地 `uploads`（`/uploads/**`），用于联调与页面闭环
- 上线期：将上传与结果落盘迁移到 COS（仅替换 StorageService 实现）

### 3.2 同步调用 vs 异步任务

**同步调用（MVP）**
- `POST` 接口直接返回生成图片 URL
- 优点：实现快，前端交互简单
- 缺点：请求耗时长，容易超时；并发控制难

**异步任务（建议用于毕设加分）**
- `POST` 创建任务 -> 返回 taskId
- 后端异步执行调用腾讯 -> 写回结果
- 前端轮询 `GET /tasks/{id}` 或使用 SSE/WebSocket

本方案默认：后端提供异步任务能力（可先同步实现，后续升级不破坏接口）

## 4. 数据库设计

### 4.1 表清单

建议新增 1 张核心表用于任务记录：
- `ai_image_record`

可选扩展：
- `ai_image_record_result`（多结果图拆表，可选）
- `ai_quota`（额度表，或用 Redis + 每日 key）

### 4.2 生成记录表 `ai_image_record`

| 字段名 | 类型 | 允许空 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT PK | 否 | 记录ID |
| user_id | BIGINT | 否 | 用户ID |
| original_image_url | TEXT | 是 | 参考图URL（可空） |
| result_image_url | TEXT | 否 | 生成图片URL |
| prompt | VARCHAR(500) | 是 | 提示词（可空） |

索引建议：
- `idx_user_id(user_id)`
 
补充说明：
- `original_image_url`：参考图允许为空
- `prompt`：提示词允许为空

## 5. 后端架构设计

### 5.1 包结构建议（参考现有 Heritage 模块分层）

- `controller`
  - `AiImageController`
- `service`
  - `AiImageService`
  - `AiImageRecordService`
- `entity / mapper`
  - `AiImageRecord` / `AiImageRecordMapper`
- `dto / vo`
  - `AiTextToImageRequest`（文生图入参）
  - `AiImageGenerateResponse`（生图返回）
  - `AiImageRecordVO`（历史记录返回）

补充说明：
- 当前实现直接在 `AiImageServiceImpl` 中调用腾讯云 SDK（未单独抽出 `TencentHunyuanClient`）
- 图生图在后端落本地参考图（`uploads/ai-ref`），并通过 `file.public-base-url` 拼接公网 URL

### 5.2 接口设计（建议）

#### 5.2.1 文生图（prompt-only）

`POST /api/customize/ai-image/text-to-image`

- Content-Type：`application/json`
- 参数（`AiTextToImageRequest`）：
  - `prompt`：string（必填）
  - `resolution`：string（可选，默认 `1024:1024`）
  - `seed`：number（可选）
  - `style`：string（可选）
  - `rspImgType`：string（建议传 `url`）

返回：
- `Result<AiImageGenerateResponse>`

#### 5.2.2 图生图（上传参考图）

`POST /api/customize/ai-image/image-to-image`

- Content-Type：`multipart/form-data`
- 参数：
  - `file`：file（必填）
  - `prompt`：string（必填）
  - `negativePrompt`：string（可选）
  - `strength`：number（可选，范围 `0~1`）
  - `resolution`：string（可选）
  - `enhanceImage`：boolean（可选）
  - `restoreFace`：boolean（可选）
  - `styles`：string[]（可选）
  - `count`：int（可选，默认 1，限制 `1~4`）
  - `rspImgType`：string（建议传 `url`）

返回：
- `Result<AiImageGenerateResponse>`

#### 5.2.3 查询用户历史记录分页

`GET /api/customize/ai-image/records`

参数：
- `page` `size`

返回分页列表（与现有 PageQuery 风格一致）。

### 5.3 关键校验与错误处理

- prompt：必填、建议 `1~1000` 字符
- refImage：可选；仅允许图片类型（jpg/png/webp），限制大小（如 5MB）
- size：仅允许白名单值（避免透传导致腾讯侧报错）
- strength：仅图生图生效，限制 `0~1`
- 并发：同一 userId 同时 RUNNING 数量限制（如 1）
- 限流：按日额度（如每天 10 次），超限返回业务错误

## 6. 腾讯混元对接设计（抽象层）

### 6.1 模式选择逻辑

- 当 `refImage` 为空：走 **文生图**（TEXT_TO_IMAGE）
- 当 `refImage` 不为空：走 **图生图**（IMAGE_TO_IMAGE），并启用 `strength`

### 6.2 输入与输出

- 输入：
  - prompt
  - refImage：建议上传 COS，得到公网 URL（或符合腾讯要求的可访问 URL）
  - 参数：style、size、n、strength
- 输出：
  - 结果图片 URL 列表（建议立刻二次保存到 COS，避免临时 URL 过期）

### 6.3 客户端封装原则

`TencentHunyuanClient` 只负责：
- 组装请求
- 调用腾讯 SDK / HTTP API
- 将响应映射为内部统一结构（`List<String>` + error）

业务层不直接依赖 SDK 类型，便于替换厂商或版本升级。

### 7.1 页面与交互

## 8. 测试与优化建议（毕设加分点）

### 8.1 功能测试
- prompt-only 生成
- refImage + prompt 生成
- 尺寸、数量、自由度参数校验
- 历史记录分页与回显

### 8.2 异常与边界
- 空 prompt / 超长 prompt
- 非图片文件 / 超大图片
- 并发超限 / 每日额度超限
- 腾讯接口超时、限流、返回错误码映射

### 8.3 优化
- 任务队列（本地线程池/消息队列/Redis 队列）
- 结果落盘（COS）+ CDN 加速
- 前端缓存最近一次结果与参数
