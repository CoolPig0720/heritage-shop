# 定制渠道模块设计方案

最后更新：2026-04-17

## 1. 模块概述

定制渠道模块用于打通"AI 智能生图 → 用户选商家 → 沟通需求 → 商家报价 → 确认定制下单"的完整闭环。用户在智能定制页通过 AI 生成满意的设计图后，可选择商家发起定制工单，双方在工单内进行纯文字沟通，商家报价后用户确认（同时选择收件地址），系统自动创建正式订单。

模块核心目标：
- 支持**用户选择商家**发起定制请求（商家画像从商品数据聚合，不改 sys_user 表）
- 支持用户与商家在工单内**纯文字沟通**（简化 IM，绑定定制上下文）
- 支持商家**报价**，用户确认报价时**选择收件地址**
- 确认后**自动创建正式订单**（复用现有订单与支付链路）
- 支持**工单状态流转**：PENDING → QUOTED → CONFIRMED → COMPLETED / CANCELLED

与现有系统的衔接：
- 前端入口：Customize.vue（AI 生图结果页"发起定制"按钮）+ 用户侧"我的定制"页面
- 商家入口：商家后台新增"定制管理"页面
- 鉴权：用户需登录（沿用现有 requiresAuth），商家操作需 MERCHANT 角色
- 订单创建：确认报价后调用 OrderService 创建定制订单，复用现有支付链路
- 商家画像：从 product + product_image 聚合，不新增数据库字段

## 2. 需求分析

### 2.1 功能需求

1. **可选商家列表**
   - 查询所有 MERCHANT 角色用户
   - 聚合每位商家的：在售商品数量、前 4 个商品封面图
   - 不在 sys_user 表新增字段，纯聚合查询

2. **发起定制请求**
   - 必填：商家ID（merchantId）、定制标题（title）、需求描述（description）
   - 可选：参考图片 URL（imageUrl，用户上传图片）
   - 创建后状态为 PENDING

3. **工单内沟通**
   - 用户与商家在同一个工单内发送纯文字消息
   - 消息区分发送者类型（USER / MERCHANT）
   - 前端轮询刷新消息列表（5 秒间隔）

4. **商家报价**
   - 商家填写报价金额（quotedPrice）
   - 仅 PENDING 状态可报价，报价后状态变为 QUOTED

5. **用户确认报价**
   - 必填：收件地址ID（addressId，从 user_address 选择）
   - 确认后自动创建正式订单（复用 OrderService）
   - 仅 QUOTED 状态可确认，确认后状态变为 CONFIRMED

6. **完成与取消**
   - 商家标记完成：CONFIRMED → COMPLETED
   - 用户或商家取消：PENDING / QUOTED → CANCELLED（CONFIRMED 之后不可取消，走售后）

### 2.2 非功能需求

1. **安全性**
   - 工单只允许参与方（发起用户或被选商家）访问
   - user_id 从 JWT 获取，禁止前端传入
   - 消息内容做长度限制（500 字符）与 XSS 过滤

2. **一致性**
   - 确认报价时校验地址归属当前用户且状态有效
   - 创建订单与更新工单状态在同一事务内
   - 订单金额使用商家报价（quotedPrice）

3. **性能**
   - 工单列表按 user_id / merchant_id 建索引
   - 消息列表按 request_id 建索引
   - 商家列表聚合查询避免 N+1

## 3. 数据库设计

### 3.1 定制工单表 `customize_request`

| 字段名 | 类型 | 长度 | 允许空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | BIGINT PK | - | 否 | AUTO_INCREMENT | 工单ID |
| user_id | BIGINT | - | 否 | - | 用户ID（关联 sys_user.id） |
| merchant_id | BIGINT | - | 否 | - | 商家ID（关联 sys_user.id） |
| title | VARCHAR | 200 | 否 | - | 定制标题 |
| description | TEXT | - | 否 | - | 需求描述 |
| image_url | VARCHAR | 500 | 是 | NULL | 用户上传的参考图片URL |
| quoted_price | DECIMAL | 10,2 | 是 | NULL | 商家报价 |
| address_id | BIGINT | - | 是 | NULL | 收件地址ID（确认时填入） |
| status | VARCHAR | 20 | 否 | PENDING | 状态：PENDING/QUOTED/CONFIRMED/COMPLETED/CANCELLED |
| order_id | BIGINT | - | 是 | NULL | 关联订单ID（确认后生成） |
| create_time | DATETIME | - | 否 | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | - | 否 | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

索引设计：
- PRIMARY KEY (`id`)
- KEY `idx_user_id` (`user_id`)
- KEY `idx_merchant_id` (`merchant_id`)
- KEY `idx_user_status` (`user_id`, `status`)
- KEY `idx_merchant_status` (`merchant_id`, `status`)
- KEY `idx_order_id` (`order_id`)

字段说明补充：
- `quoted_price`：商家报价，PENDING 时为 NULL，报价后写入
- `address_id`：用户确认报价时选择的收货地址ID，确认后写入
- `order_id`：确认后自动创建订单写入，关联 orders.id
- `status` 流转：PENDING → QUOTED → CONFIRMED → COMPLETED，任意阶段可 CANCELLED（CONFIRMED 后不可取消）

### 3.2 定制沟通消息表 `customize_message`

| 字段名 | 类型 | 长度 | 允许空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | BIGINT PK | - | 否 | AUTO_INCREMENT | 消息ID |
| request_id | BIGINT | - | 否 | - | 工单ID（关联 customize_request.id） |
| sender_id | BIGINT | - | 否 | - | 发送者ID（关联 sys_user.id） |
| sender_type | VARCHAR | 10 | 否 | - | 发送者类型：USER / MERCHANT |
| content | TEXT | - | 否 | - | 消息内容（纯文字） |
| create_time | DATETIME | - | 否 | CURRENT_TIMESTAMP | 发送时间 |

索引设计：
- PRIMARY KEY (`id`)
- KEY `idx_request_id` (`request_id`)
- KEY `idx_request_created` (`request_id`, `create_time`)

字段说明补充：
- `sender_type`：区分用户消息和商家消息，前端据此做左右气泡布局
- `content`：纯文字消息，不含图片，长度限制 500 字符

### 3.3 关系说明

```
sys_user (1) —— (N) customize_request   （用户发起）
sys_user (1) —— (N) customize_request   （商家接收，merchant_id）
customize_request (1) —— (N) customize_message
customize_request (1) —— (0..1) orders   （确认后关联）
```

## 4. 后端架构设计

### 4.1 分层结构

- Entity：`CustomizeRequest` → `customize_request`、`CustomizeMessage` → `customize_message`
- Mapper：`CustomizeRequestMapper extends BaseMapper<CustomizeRequest>`、`CustomizeMessageMapper extends BaseMapper<CustomizeMessage>`
- Service：`CustomizeRequestService`（工单业务）、`CustomizeMessageService`（消息业务）
- Controller：`CustomizeRequestController`（工单接口）、`CustomizeMerchantController`（商家列表）
- DTO/VO：入参与出参分离，统一返回 `Result<T>`

### 4.2 DTO / VO 设计

1. **发起定制请求**

   `CustomizeRequestCreateRequest`
   - merchantId：必填
   - title：必填（1~200 字符）
   - description：必填（1~2000 字符）
   - imageUrl：可选（用户上传参考图片）

2. **商家报价请求**

   `CustomizeQuoteRequest`
   - quotedPrice：必填（> 0）

3. **用户确认报价请求**

   `CustomizeConfirmRequest`
   - addressId：必填

4. **发送消息请求**

   `CustomizeMessageCreateRequest`
   - content：必填（1~500 字符）

5. **更新状态请求**

   `CustomizeStatusUpdateRequest`
   - status：必填（COMPLETED / CANCELLED）

6. **商家卡片返回**

   `MerchantCardVO`
   - id（商家用户ID）
   - name（商家名称）
   - avatar（商家头像URL）
   - productCount（在售商品数量）
   - coverImageUrls：`List<String>`（前 4 个商品封面图URL）

7. **工单返回**

   `CustomizeRequestVO`
   - id / userId / merchantId / title / description / imageUrl
   - quotedPrice / addressId / status / orderId
   - createTime / updateTime
   - userName / merchantName（聚合填充）
   - orderNo（关联订单号，可空）

8. **消息返回**

   `CustomizeMessageVO`
   - id / requestId / senderId / senderType / content / createTime
   - senderName（聚合填充）

### 4.3 业务规则

- 发起定制：merchantId 必须是 MERCHANT 角色的有效用户
- 沟通消息：仅工单参与方（user_id 或 merchant_id）可发送和查看
- 商家报价：仅 PENDING 状态可报价，quotedPrice > 0
- 用户确认：仅 QUOTED 状态可确认，addressId 必须归属当前用户且有效
- 确认时创建订单：在同一事务内完成——
  - 读取 addressId 对应的收货地址，写入订单地址快照
  - 创建 orders 记录（status=UNPAID，totalAmount=quotedPrice）
  - 创建 order_item 记录（商品名=工单 title，单价=quotedPrice，数量=1）
  - 更新 customize_request 的 orderId 和 status
- 完成标记：仅 CONFIRMED 状态可标记 COMPLETED（商家操作）
- 取消：PENDING / QUOTED 状态可取消（用户或商家均可操作），CONFIRMED 后不可取消
- 工单权限：查看/操作工单时校验当前用户是参与方

## 5. 后端接口设计

接口鉴权：本模块接口默认需要登录（JWT），user_id 统一从登录态获取。

### 5.1 商家列表接口

#### 5.1.1 可选商家列表

- GET `/api/customize/merchants`
- Response：`Result<List<MerchantCardVO>>`
- 说明：聚合查询所有 MERCHANT 角色用户，关联商品信息

### 5.2 定制工单接口（统一前缀：`/api/customize/requests`）

#### 5.2.1 发起定制请求

- POST `/api/customize/requests`
- Body：`CustomizeRequestCreateRequest`
- Response：`Result<Long>`（返回工单ID）

#### 5.2.2 我的定制列表（用户侧）

- GET `/api/customize/requests/mine`
- Query：`page / size / status(可选)`
- Response：`Result<Page<CustomizeRequestVO>>`

#### 5.2.3 收到的定制列表（商家侧）

- GET `/api/customize/requests/received`
- Query：`page / size / status(可选)`
- Response：`Result<Page<CustomizeRequestVO>>`

#### 5.2.4 工单详情

- GET `/api/customize/requests/{id}`
- Response：`Result<CustomizeRequestVO>`
- 校验：当前用户为工单参与方

#### 5.2.5 商家报价

- PUT `/api/customize/requests/{id}/quote`
- Body：`CustomizeQuoteRequest`
- Response：`Result<Void>`
- 校验：当前用户为 merchant_id 对应商家，状态为 PENDING

#### 5.2.6 用户确认报价

- PUT `/api/customize/requests/{id}/confirm`
- Body：`CustomizeConfirmRequest`
- Response：`Result<Long>`（返回订单ID）
- 校验：当前用户为工单发起用户，状态为 QUOTED

#### 5.2.7 更新工单状态

- PUT `/api/customize/requests/{id}/status`
- Body：`CustomizeStatusUpdateRequest`
- Response：`Result<Void>`
- 说明：COMPLETED 由商家操作（CONFIRMED → COMPLETED），CANCELLED 由双方操作（PENDING/QUOTED → CANCELLED）

### 5.3 沟通消息接口（统一前缀：`/api/customize/requests/{requestId}/messages`）

#### 5.3.1 发送消息

- POST `/api/customize/requests/{requestId}/messages`
- Body：`CustomizeMessageCreateRequest`
- Response：`Result<Long>`（返回消息ID）
- 校验：当前用户为工单参与方

#### 5.3.2 消息列表

- GET `/api/customize/requests/{requestId}/messages`
- Response：`Result<List<CustomizeMessageVO>>`
- 校验：当前用户为工单参与方
- 说明：按 create_time 正序返回，前端轮询刷新（5 秒间隔）

## 6. 前端架构设计

### 6.1 路由与页面

新增路由（用户侧，嵌套在 MainLayout 下）：

| 路径 | 组件 | 说明 |
| --- | --- | --- |
| `/customize/merchants` | CustomizeMerchants.vue | 选择商家页（商家卡片列表） |
| `/customize/requests` | CustomizeRequests.vue | 我的定制（用户工单列表） |
| `/customize/requests/:id` | CustomizeRequestDetail.vue | 工单详情+沟通页 |

新增路由（商家侧，嵌套在 MerchantLayout 下）：

| 路径 | 组件 | 说明 |
| --- | --- | --- |
| `/merchant/customize` | merchant/CustomizeRequests.vue | 商家定制管理（收到的工单列表） |
| `/merchant/customize/:id` | merchant/CustomizeRequestDetail.vue | 商家工单详情+沟通+报价 |

### 6.2 API 封装

新增 `frontend/src/api/customize.js`：

- getMerchantList() — 获取可选商家列表
- createCustomizeRequest(data) — 发起定制
- pageMyRequests(params) — 我的定制列表
- pageReceivedRequests(params) — 收到的定制列表
- getCustomizeRequestDetail(id) — 工单详情
- quoteCustomizeRequest(id, data) — 商家报价
- confirmCustomizeRequest(id, data) — 用户确认报价
- updateCustomizeRequestStatus(id, data) — 更新状态
- sendCustomizeMessage(requestId, data) — 发送消息
- listCustomizeMessages(requestId) — 消息列表

### 6.3 交互设计要点

1. **发起定制入口**
   - Customize.vue 中 AI 生图结果区域新增"发起定制"按钮
   - 点击后弹出对话框：填标题+描述+上传参考图片
   - 对话框内"选择商家"按钮跳转至商家选择页

2. **商家选择页**
   - 展示商家卡片（头像+名称+商品数+商品封面缩略图）
   - 点选商家后自动回填，返回发起定制对话框
   - 若从 Customize.vue 带入 imageUrl 则自动填充

3. **工单详情+沟通页（用户侧与商家侧共用交互模式）**
   - 顶部：工单信息（标题、描述、参考图片预览、状态、报价）
   - 中部：消息列表（左右气泡布局，用户靠右/商家靠左）
   - 底部：输入框 + 发送按钮
   - 操作区：商家-报价按钮/完成按钮；用户-确认报价按钮/取消按钮
   - 消息轮询：页面打开期间每 5 秒调用消息列表接口

4. **确认报价交互**
   - 用户点击"确认报价"后弹出选择收件地址对话框
   - 调用现有 user_address 接口获取地址列表
   - 选择地址后调用确认接口，成功后跳转至订单详情

### 6.4 商家侧布局对齐

商家后台新增"定制管理"菜单项，与现有"商品管理"页面保持 UI 统一（参考多角色 UI 样式统一规范），表格/分页/操作按钮风格对齐 admin 端。

## 7. 业务流程

### 7.1 发起定制流程

1. 用户在 Customize.vue 生成满意的 AI 图
2. 点击"发起定制" → 弹出对话框（填标题+描述+附AI图）
3. 点击"选择商家" → 跳转商家选择页 → 点选一个商家 → 返回
4. 提交 → 后端创建 customize_request（PENDING）→ 返回工单ID

### 7.2 沟通与报价流程

1. 商家在后台"定制管理"看到新工单
2. 点击进入工单详情页 → 查看需求 → 发消息沟通
3. 商家填写报价 → 调用报价接口 → 状态变为 QUOTED

### 7.3 确认与下单流程

1. 用户在"我的定制"看到商家已报价
2. 进入工单详情 → 点击"确认报价" → 弹出选择收件地址
3. 选择地址后确认 → 后端在同一事务内：
   - 读取 addressId 对应的收货地址
   - 创建 orders（status=UNPAID，totalAmount=quotedPrice）
   - 创建 order_item（商品快照）
   - 更新 customize_request（orderId, status=CONFIRMED）
4. 返回订单ID → 用户可继续支付（复用现有支付链路）

### 7.4 完成流程

1. 商家在工单详情页标记"完成" → 状态变为 COMPLETED

## 8. 异常与边界

- 商家ID无效或非 MERCHANT 角色：提示"商家不存在"
- 重复报价：仅 PENDING 可报价，其他状态提示"工单状态不支持报价"
- 确认时地址无效：提示"收件地址不存在或无效"
- 确认时地址不归属当前用户：提示"无权限使用该地址"
- 重复确认：仅 QUOTED 可确认
- 已取消工单不可操作：提示"工单已取消"
- 消息内容为空或超长：提示"消息内容不合法"
- 非参与方访问工单：提示"无权限访问"
- 确认后不可取消：CONFIRMED 状态取消提示"已确认的工单不可取消，如需退款请联系商家"
