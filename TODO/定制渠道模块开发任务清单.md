## 阶段四：后端业务逻辑层

### 4.1 Service 接口与实现
- [x] 创建 `CustomizeRequestService` 接口及实现类
  - [x] 实现可选商家列表（聚合 MERCHANT 用户 + 商品数量 + 封面图）
  - [x] 实现发起定制请求（校验商家角色，创建工单 PENDING）
  - [x] 实现我的定制列表分页（按 user_id 查询，可按 status 过滤）
  - [x] 实现收到的定制列表分页（按 merchant_id 查询，可按 status 过滤）
  - [x] 实现工单详情（校验参与方权限，聚合用户名/商家名/订单号）
  - [x] 实现商家报价（校验 PENDING 状态 + 归属，写入 quotedPrice → QUOTED）
  - [x] 实现用户确认报价（校验 QUOTED 状态 + 地址归属，创建订单 + 更新工单 → CONFIRMED）
  - [x] 实现更新状态（COMPLETED / CANCELLED 状态流转校验）
- [x] 创建 `CustomizeMessageService` 接口及实现类
  - [x] 实现发送消息（校验参与方权限，内容长度与 XSS 过滤）
  - [x] 实现消息列表查询（按 request_id + create_time 正序）

### 4.2 业务规则与校验
- [x] 商家ID校验（merchantId 必须是 MERCHANT 角色有效用户）
- [x] 工单参与方权限校验（查看/操作工单必须为 user_id 或 merchant_id）
- [x] 状态流转校验（PENDING→QUOTED→CONFIRMED→COMPLETED，PENDING/QUOTED→CANCELLED）
- [x] 报价金额校验（quotedPrice > 0）
- [x] 确认报价时地址校验（归属当前用户且有效）
- [x] 确认报价事务一致性（创建订单 + 更新工单在同一事务）
- [x] 消息内容校验（1~500 字符，XSS 过滤）
- [x] CONFIRMED 后不可取消（提示走售后）
