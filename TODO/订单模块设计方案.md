# 订单模块设计方案

最后更新：2026-02-10

## 1. 模块概述

订单模块用于承接“购物车（可变）→ 订单（快照）→ 支付（状态机）”的交易链路，面向所有登录用户提供购物车条目增删改查、下单（从购物车生成订单快照）、订单查询、发起支付与模拟支付的能力。

按该思路，最少需要 4 张表（购物车条目 1 张、订单 2 张、支付 1 张）：

- 购物车：`cart_item`（可变数据）
- 订单：`orders` + `order_item`（快照数据）
- 支付：`payment`（状态机数据）

本模块与商品模块的关系：

- `cart_item.product_id -> product.id`（不使用数据库外键，关联一致性由业务层维护）
- 购物车展示需要聚合商品信息（名称、价格、封面图、上架状态等）
- 下单时需要把商品信息写入订单明细快照（商品名、封面、单价、数量、小计）
- 本项目当前商品表无库存字段，本模块不做库存锁定/扣减

当前落地情况（与代码一致）：

- 前端存在购物车页面 `frontend/src/views/Cart.vue`，但数据为前端 mock
- 前端存在订单页面 `frontend/src/views/Orders.vue`，但数据为前端 mock
- 后端暂无购物车/订单/支付相关表与接口

## 2. 需求分析

### 2.1 功能需求

1. **加入购物车（登录用户）**
   - 从商品详情/列表点击“加入购物车”
   - 若购物车已存在同一 `product_id`，则累加数量
   - 默认 `selected=1`（加入后默认勾选）
   - 仅允许加入上架商品（`product.status = 1`）
   - 购物车条目支持软删状态（`status`），列表只返回有效条目

2. **购物车列表（登录用户）**
   - 查询当前用户的购物车条目
   - 返回条目明细 + 聚合的商品展示信息（name/price/coverImageUrl/status 等）

3. **修改数量（登录用户）**
   - 数量最小为 1
   - 本项目当前商品表无库存字段，购物车阶段不做库存上限校验

4. **勾选/取消勾选（登录用户）**
   - 单条勾选状态切换
   - 支持全选/全不选（可选增强）

5. **删除条目（登录用户）**
   - 删除单条购物车记录
   - 支持软删（`status=0`）或物理删（可选），推荐软删
   - 支持清空（可选增强）：清空所有 / 清空已勾选

6. **下单（从购物车生成订单快照，登录用户）**
   - 从购物车中读取“已勾选且有效”的条目
   - 校验商品存在且上架
   - 以商品表实时价格计算订单总额
   - 生成订单主表 `orders` 与订单明细快照 `order_item`
   - 写入地址快照字段（从收货地址模块读取后写死到订单）
   - 下单成功后将已下单的购物车条目置为未勾选或删除（按产品策略二选一）

7. **发起支付与模拟支付（登录用户）**
   - 为 UNPAID 订单创建支付单 `payment`（INIT）
   - 提供 MOCK 支付接口，将支付状态置为 SUCCESS/FAIL，并驱动订单状态流转

### 2.2 非功能需求

1. **安全性**
   - 购物车只允许访问当前登录用户的数据
   - `user_id` 必须从 JWT 中取，禁止前端传入

2. **一致性**
   - 同一用户同一商品最多一条记录：使用唯一约束 `(user_id, product_id)` 保证
   - 购物车价格不落库：以商品表实时价格为准
   - 订单价格写快照：下单瞬间写死到 `order_item.unit_price`，订单总额来自快照汇总
   - 订单号/支付单号全局唯一：`order_no`、`pay_no` 需唯一约束
   - 订单地址使用快照字段，避免用户修改地址影响历史订单

3. **性能**
   - 购物车列表按 `user_id` 查询，建立索引
   - 列表聚合商品信息时避免 N+1 查询（批量查询商品与封面图）
   - 订单明细按 `order_id` 查询，建立索引

## 3. 数据库设计

### 3.1 购物车条目表 `cart_item`

| 字段名       | 类型        | 允许空 | 默认值            | 说明 |
| ------------ | ----------- | ------ | ----------------- | ---- |
| id           | BIGINT PK   | 否     | AUTO_INCREMENT    | 主键 |
| user_id      | BIGINT      | 否     | -                 | 用户ID（`sys_user.id`） |
| product_id   | BIGINT      | 否     | -                 | 商品ID（`product.id`） |
| quantity     | INT         | 否     | 1                 | 数量（>=1） |
| selected     | TINYINT(1)  | 否     | 1                 | 是否勾选：1-勾选，0-未勾选 |
| status       | TINYINT(1)  | 否     | 1                 | 状态：1-有效，0-删除/失效（软删） |
| create_time  | DATETIME    | 否     | CURRENT_TIMESTAMP | 创建时间 |
| update_time  | DATETIME    | 否     | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

索引与约束建议：

- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_user_product` (`user_id`, `product_id`)
- KEY `idx_user_id` (`user_id`)
- KEY `idx_user_selected` (`user_id`, `selected`)
- KEY `idx_user_status` (`user_id`, `status`)

### 3.2 订单主表 `orders`

| 字段名            | 类型         | 允许空 | 默认值            | 说明 |
| ----------------- | ------------ | ------ | ----------------- | ---- |
| id                | BIGINT PK    | 否     | AUTO_INCREMENT    | 主键 |
| order_no          | VARCHAR(64)  | 否     | -                 | 业务订单号（唯一） |
| user_id           | BIGINT       | 否     | -                 | 用户ID |
| address_id        | BIGINT       | 否     | -                 | 收货地址ID（下单时选择的 `user_address.id`） |
| total_amount      | DECIMAL(10,2)| 否     | 0                 | 订单总金额（来自快照汇总） |
| status            | VARCHAR(20)  | 否     | UNPAID            | 订单状态：UNPAID/PAID/CANCELLED |
| receiver_name     | VARCHAR(50)  | 否     | -                 | 收货人姓名（快照，来自 address_id 对应地址） |
| receiver_phone    | VARCHAR(20)  | 否     | -                 | 收货人手机号（快照，来自 address_id 对应地址） |
| region_name_path  | VARCHAR(512) | 否     | -                 | 地区路径（快照，来自 address_id 对应地址） |
| detail_address    | VARCHAR(255) | 否     | -                 | 详细地址（快照，来自 address_id 对应地址） |
| create_time       | DATETIME     | 否     | CURRENT_TIMESTAMP | 创建时间 |
| update_time       | DATETIME     | 否     | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| paid_time         | DATETIME     | 是     | NULL              | 支付成功时间（可选） |
| cancel_time       | DATETIME     | 是     | NULL              | 取消时间（可选） |

索引与约束建议：

- UNIQUE KEY `uk_order_no` (`order_no`)
- KEY `idx_user_id` (`user_id`)
- KEY `idx_user_status` (`user_id`, `status`)
- KEY `idx_user_address` (`user_id`, `address_id`)

### 3.3 订单明细表（商品快照）`order_item`

| 字段名          | 类型          | 允许空 | 默认值            | 说明 |
| --------------- | ------------- | ------ | ----------------- | ---- |
| id              | BIGINT PK     | 否     | AUTO_INCREMENT    | 主键 |
| order_id        | BIGINT        | 否     | -                 | 订单ID（逻辑关联 orders.id） |
| product_id      | BIGINT        | 否     | -                 | 商品ID |
| product_name    | VARCHAR(100)  | 否     | -                 | 商品名称（快照） |
| cover_image_url | VARCHAR(512)  | 是     | NULL              | 封面图（快照） |
| unit_price      | DECIMAL(10,2) | 否     | 0                 | 下单单价（快照） |
| quantity        | INT           | 否     | 1                 | 数量 |
| subtotal        | DECIMAL(10,2) | 否     | 0                 | 小计（unit_price * quantity） |
| create_time     | DATETIME      | 否     | CURRENT_TIMESTAMP | 创建时间 |

索引建议：

- KEY `idx_order_id` (`order_id`)

### 3.4 支付表 `payment`

| 字段名      | 类型          | 允许空 | 默认值            | 说明 |
| ----------- | ------------- | ------ | ----------------- | ---- |
| id          | BIGINT PK     | 否     | AUTO_INCREMENT    | 主键 |
| pay_no      | VARCHAR(64)   | 否     | -                 | 支付单号（唯一） |
| order_id    | BIGINT        | 否     | -                 | 订单ID（逻辑关联 orders.id） |
| amount      | DECIMAL(10,2) | 否     | 0                 | 支付金额（一般等于订单总额） |
| channel     | VARCHAR(20)   | 否     | MOCK              | 支付渠道（MOCK/WECHAT/ALIPAY...） |
| status      | VARCHAR(20)   | 否     | INIT              | 支付状态：INIT/SUCCESS/FAIL |
| create_time | DATETIME      | 否     | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME      | 否     | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| paid_time   | DATETIME      | 是     | NULL              | 支付成功时间（可选） |
| fail_reason | VARCHAR(255)  | 是     | NULL              | 失败原因（可选） |

索引与约束建议：

- UNIQUE KEY `uk_pay_no` (`pay_no`)
- KEY `idx_order_id` (`order_id`)

### 3.5 关系说明

```
sys_user (1) —— (N) cart_item
product   (1) —— (N) cart_item
orders    (1) —— (N) order_item
orders    (1) —— (N) payment
```

## 4. 后端架构设计

### 4.1 分层结构

- Entity：`CartItem` -> `cart_item`
- Mapper：`CartItemMapper extends BaseMapper<CartItem>`
- Service：`CartService`（以 userId 为维度封装购物车业务）
- Controller：`CartController`（从 JWT 取 userId）
- Entity：`Orders` / `OrderItem` / `Payment` 对应三张交易表
- Service：`OrderService`（创建订单、查询订单）/ `PaymentService`（创建支付单、模拟支付）
- Controller：`OrderController` / `PaymentController`
- DTO/VO：入参与出参分离，统一返回 `Result<T>`

### 4.2 DTO / VO 设计

1. **新增条目请求**

`CartItemAddRequest`

- productId：必填
- quantity：可选（默认 1，必须 >=1）

2. **修改数量请求**

`CartItemQuantityUpdateRequest`

- quantity：必填（>=1）

3. **勾选状态请求**

`CartItemSelectedUpdateRequest`

- selected：必填（0/1）

4. **购物车条目返回**

`CartItemVO`（包含商品展示信息）

- id / productId / quantity / selected
- productName / price / coverImageUrl / status

5. **购物车汇总返回（可选）**

`CartSummaryVO`

- totalCount：购物车条目数
- selectedCount：已勾选条目数
- selectedAmount：已勾选金额合计

6. **创建订单请求**

`OrderCreateRequest`

- addressId：必填（从收货地址模块选择）

7. **订单返回**

`OrderVO`

- id / orderNo / totalAmount / status / createTime
- 地址快照字段：receiverName/receiverPhone/regionNamePath/detailAddress
- items：`List<OrderItemVO>`

8. **订单明细返回**

`OrderItemVO`

- productId / productName / coverImageUrl / unitPrice / quantity / subtotal

9. **创建支付单请求**

`PaymentCreateRequest`

- channel：可选（默认 MOCK）

10. **模拟支付动作请求**

`PaymentActionRequest`

- action：必填（CONFIRM/CANCEL）

### 4.3 业务规则

- 加购时若商品不存在或非上架：抛出业务异常
- 同一用户同一商品：
  - 已存在：数量累加
  - 不存在：插入新记录
- 修改/删除必须校验归属：`cart_item.user_id == currentUserId`
- 下单：必须存在至少一条已勾选且有效的购物车条目
- 下单：订单金额以订单明细快照汇总计算
- 支付状态机：
  - payment：INIT -> SUCCESS / FAIL
  - orders：UNPAID -> PAID（支付成功驱动），UNPAID -> CANCELLED（取消）

## 5. 后端接口设计

接口鉴权：除 `/api/heritage/**` 允许匿名外，本模块接口默认需要登录（JWT），`user_id` 统一从登录态获取。

### 5.1 购物车条目接口（统一前缀：`/api/cart`）

#### 5.1.1 加入购物车

- POST `/api/cart/items`
- Body：`{ productId, quantity? }`
- Response：`Result<Long>`（返回 cartItemId）

#### 5.1.2 购物车列表

- GET `/api/cart/items`
- Response：`Result<List<CartItemVO>>`

#### 5.1.3 修改数量

- PUT `/api/cart/items/{id}/quantity`
- Body：`{ quantity }`
- Response：`Result<Void>`

#### 5.1.4 勾选/取消勾选

- PUT `/api/cart/items/{id}/selected`
- Body：`{ selected }`
- Response：`Result<Void>`

#### 5.1.5 删除条目

- DELETE `/api/cart/items/{id}`
- Response：`Result<Void>`

#### 5.1.6 汇总信息（可选）

- GET `/api/cart/summary`
- Response：`Result<CartSummaryVO>`

### 5.2 订单接口（统一前缀：`/api/orders`）

#### 5.2.1 从购物车创建订单

- POST `/api/orders`
- Body：`{ addressId }`
- Response：`Result<Long>`（返回 orderId）
  - 服务端基于 `addressId` 读取 `user_address` 并自动填充订单地址快照字段（receiver_name/receiver_phone/region_name_path/detail_address）
  - 校验 `addressId` 归属当前用户且 `user_address.status=1`

#### 5.2.2 订单列表

- GET `/api/orders`
- Query：`page / size / status(可选)`
- Response：`Result<Page<OrderVO>>`

#### 5.2.3 订单详情

- GET `/api/orders/{id}`
- Response：`Result<OrderVO>`

#### 5.2.4 取消订单（可选）

- PUT `/api/orders/{id}/cancel`
- Response：`Result<Void>`

### 5.3 支付接口（统一前缀：`/api/payments`）

#### 5.3.1 创建支付单

- POST `/api/payments`
- Body：`{ orderId, channel? }`
- Response：`Result<PaymentVO>`（返回 paymentId、payNo、payUrl、status）

`PaymentVO`（建议最小字段）：

- id
- payNo
- status（INIT/SUCCESS/FAIL）
- amount
- payUrl（MOCK 场景返回前端可生成二维码的 URL，例如：`{frontBaseUrl}/pay/mock?paymentId=xxx`）

#### 5.3.2 模拟支付（MOCK）

- POST `/api/payments/{id}/mock-pay`
- Body：`{ action }`（action=CONFIRM/CANCEL）
- Response：`Result<PaymentVO>`（返回最新支付单状态）

说明：

- action=CONFIRM：服务端按“模拟渠道规则”决定 SUCCESS/FAIL（用户不主动选择失败）
- action=CANCEL：将本次支付尝试置为 FAIL（fail_reason=USER_CANCELLED），订单保持 UNPAID

#### 5.3.3 查询支付单状态（可选）

- GET `/api/payments/{id}`
- Response：`Result<PaymentVO>`（至少包含 id、status、paidTime、failReason）

## 7. 业务流程

### 7.1 加入购物车流程

1. 用户在商品页点击“加入购物车”
2. 前端调用 `POST /api/cart/items`
3. 后端校验登录态 -> 校验商品存在且上架 -> 合并或新增条目
4. 返回 cartItemId，前端提示成功并更新购物车数量（可选）

### 7.2 下单流程（购物车 -> 订单快照）

1. 进入购物车页：拉取条目列表
2. 用户勾选/修改数量：实时调用更新接口（或本地暂存后统一提交）
3. 点击“结算”：跳转订单确认页并选择收货地址
4. 前端调用 `POST /api/orders` 创建订单
5. 后端读取 `addressId` 对应的用户地址 -> 将地址字段复制到订单主表快照字段
6. 后端读取已勾选条目 -> 写入订单与订单明细快照 -> 返回 orderId

### 7.3 支付流程（订单 -> 支付状态机）

1. 用户在订单页点击“支付”
2. 前端调用 `POST /api/payments` 创建支付单（INIT），拿到 payUrl
3. 前端展示二维码（二维码内容=payUrl）或直接跳转 payUrl 打开“模拟收银台”页
4. 用户在“模拟收银台”点击“确认支付”或“取消支付”
5. “模拟收银台”调用 `POST /api/payments/{id}/mock-pay` 提交动作（CONFIRM/CANCEL）
6. 订单页轮询 `GET /api/payments/{id}` 或刷新订单列表，直到订单变更为 PAID 或支付失败

#### 7.3.1 简单支付实现方案（推荐：MOCK 收银台确认/取消）

核心目标：能稳定驱动“订单支付成功/失败”的状态流转，并为后续接入真实支付保留扩展点。

约定：

- 订单是否已支付以 `orders.status` 为准：UNPAID/PAID/CANCELLED
- `orders.paid_time` 仅作为展示字段，支付成功时写入
- `payment` 记录一次支付尝试，`payment.status` 负责表达该次尝试结果：INIT/SUCCESS/FAIL

服务端建议实现（简单且不容易出错）：

1. 创建支付单 `POST /api/payments`
   - 校验订单归属当前用户
   - 仅允许 `orders.status=UNPAID` 创建支付单
   - 生成 `pay_no`（保证唯一）并插入 `payment`：
     - amount = orders.total_amount
     - channel = MOCK
     - status = INIT
   - 返回 `payUrl`（供前端生成二维码/跳转收银台）
   - 建议同一订单只保留一个进行中的 INIT 支付单：
     - 若已存在 INIT，则直接返回该支付单（避免重复创建导致页面判断复杂）

2. 模拟支付动作 `POST /api/payments/{id}/mock-pay`
   - 校验支付单归属当前用户（通过 payment.order_id -> orders.user_id）
   - 幂等处理：
     - payment.status 已为 SUCCESS/FAIL：直接返回成功（不重复变更）
   - action=CANCEL：
     - 将本次支付尝试置为 FAIL（fail_reason=USER_CANCELLED），订单保持 UNPAID
   - action=CONFIRM：
     - 若已超时（例如 `now - payment.create_time > 10min`）：置为 FAIL（fail_reason=TIMEOUT）
     - 否则按“模拟渠道规则”决定 SUCCESS/FAIL（用户不主动选择失败）
       - 示例：90% SUCCESS、10% FAIL（fail_reason=CHANNEL_ERROR）
     - SUCCESS：同一事务更新 payment=SUCCESS（写 paid_time）并将 orders 从 UNPAID 更新为 PAID（写 paid_time）
     - FAIL：更新 payment=FAIL、写 fail_reason，订单仍保持 UNPAID，允许用户再次发起支付

---

## 8. 异常与边界

- 商品不存在：提示“商品不存在”
- 商品下架：提示“商品已下架，无法加入购物车”
- 数量非法（<1）：提示“数量不合法”
- 访问他人条目：提示“无权限访问”（403）
- 购物车无已选条目：提示“请先勾选要结算的商品”
- 订单非 UNPAID 不允许再次发起支付：提示“订单状态不支持支付”
- 重复创建支付单：若已存在 INIT 支付单则直接返回该支付单
- 重复调用 mock-pay：已成功/失败的支付单直接返回成功（幂等）
- 确认支付可能失败：模拟渠道失败（CHANNEL_ERROR）或支付超时（TIMEOUT）
