# 资讯模块设计方案

## 1. 模块概述

资讯模块负责系统内公告与非遗故事的发布、展示与详情查询，覆盖两类使用场景：

1. **管理端（仅管理员）**：公告的增删改查、非遗故事的增删改查，包括发布/草稿状态管理与置顶功能。
2. **前台展示（所有登录用户）**：在资讯页面通过 Tab 切换查看公告列表与非遗故事列表，点击进入详情页。

本模块包含两个子模块——公告与非遗故事，两者业务逻辑相似（标题 + 富文本内容 + 状态 + 置顶），但语义独立，因此分表设计。非遗故事可选择性关联已有的非遗项目（`heritage_project`）。内容字段存储富文本 HTML，支持在正文中嵌入图片（通过文件上传接口获取 URL 后插入）。

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 公告管理（仅 ADMIN）

1. **新增公告**
   - 必填字段：标题 `title`、内容 `content`（富文本 HTML）
   - 可选字段：是否置顶 `is_top`
   - 状态字段：`status`（1-发布，0-草稿），创建时默认发布

2. **编辑公告**
   - 可编辑：标题、内容（富文本）、状态、是否置顶

3. **删除公告**
   - 管理员可删除任意公告

4. **公告管理列表**
   - 支持分页查询
   - 支持按标题关键词搜索、按状态筛选

#### 2.1.2 非遗故事管理（仅 ADMIN）

1. **新增非遗故事**
   - 必填字段：标题 `title`、内容 `content`（富文本 HTML，支持嵌入图片）
   - 可选字段：关联非遗项目 `heritage_project_id`、是否置顶 `is_top`
   - 状态字段：`status`（1-发布，0-草稿），创建时默认发布

2. **编辑非遗故事**
   - 可编辑：标题、内容（富文本）、关联非遗项目、状态、是否置顶

3. **删除非遗故事**
   - 管理员可删除任意非遗故事

4. **非遗故事管理列表**
   - 支持分页查询
   - 支持按标题关键词搜索、按状态筛选、按关联非遗项目筛选

#### 2.1.3 前台资讯展示（所有登录用户）

1. **资讯页面**
   - 页面含"公告"和"非遗故事"两个 Tab，默认展示公告
   - 公告列表：展示已发布公告，置顶优先，按创建时间倒序
   - 非遗故事列表：展示已发布故事，置顶优先，按创建时间倒序

2. **公告详情页**
   - 展示公告标题、富文本内容（含嵌入图片）、发布时间

3. **非遗故事详情页**
   - 展示故事标题、富文本内容（含嵌入图片）、关联非遗项目（如有，可点击跳转）、发布时间

### 2.2 非功能需求

1. **安全性**
   - 采用 JWT + Spring Security 认证
   - 管理端接口仅 ADMIN 角色可访问
   - 前台展示接口允许所有登录用户访问

2. **性能**
   - 管理列表分页查询
   - `status`、`is_top` 等字段建立索引
   - 前台列表查询可按需使用缓存（可选）

3. **可维护性**
   - 分层结构：Controller / Service / Mapper / Entity / DTO
   - 统一返回结构 `Result<T>`

## 3. 数据库设计

### 3.1 公告表 `announcement`

| 字段名       | 类型     | 长度 | 允许空 | 默认值            | 说明                     |
| ------------ | -------- | ---- | ------ | ----------------- | ------------------------ |
| id           | BIGINT   | -    | 否     | -                 | 公告ID，主键，自增       |
| title        | VARCHAR  | 200  | 否     | -                 | 公告标题                 |
| content      | LONGTEXT | -    | 否     | -                 | 公告内容（富文本 HTML）  |
| status       | TINYINT  | 1    | 否     | 1                 | 状态：1-发布，0-草稿     |
| is_top       | TINYINT  | 1    | 否     | 0                 | 是否置顶：1-是，0-否     |
| create_time  | DATETIME | -    | 否     | CURRENT_TIMESTAMP | 创建时间                 |
| update_time  | DATETIME | -    | 否     | CURRENT_TIMESTAMP | 更新时间（自动更新）     |

**索引设计：**
- PRIMARY KEY (`id`)
- KEY `idx_status` (`status`)
- KEY `idx_is_top` (`is_top`)

### 3.2 非遗故事表 `heritage_story`

| 字段名               | 类型     | 长度 | 允许空 | 默认值            | 说明                               |
| -------------------- | -------- | ---- | ------ | ----------------- | ---------------------------------- |
| id                   | BIGINT   | -    | 否     | -                 | 故事ID，主键，自增                 |
| title                | VARCHAR  | 200  | 否     | -                 | 故事标题                           |
| content              | LONGTEXT | -    | 否     | -                 | 故事内容（富文本 HTML，支持图片）  |
| heritage_project_id  | BIGINT   | -    | 是     | NULL              | 关联非遗项目ID（可选）             |
| status               | TINYINT  | 1    | 否     | 1                 | 状态：1-发布，0-草稿               |
| is_top               | TINYINT  | 1    | 否     | 0                 | 是否置顶：1-是，0-否               |
| create_time          | DATETIME | -    | 否     | CURRENT_TIMESTAMP | 创建时间                           |
| update_time          | DATETIME | -    | 否     | CURRENT_TIMESTAMP | 更新时间（自动更新）               |

**索引设计：**
- PRIMARY KEY (`id`)
- KEY `idx_status` (`status`)
- KEY `idx_heritage_project_id` (`heritage_project_id`)
- KEY `idx_is_top` (`is_top`)

### 3.3 表关系说明

```
heritage_project (1) —— (0..N) heritage_story   （可选关联）
```

- `heritage_story.heritage_project_id -> heritage_project.id`
- 不加外键约束，关联一致性由业务层保证
- 公告表无外部关联，独立存储

### 3.4 设计说明

1. **为何不合并为单表**：公告与非遗故事虽然字段相似，但语义完全不同（公告是平台通知，非遗故事是文化内容），合并后需要 type 字段区分，查询时需额外过滤，且后续各自扩展字段会互相影响。
2. **置顶排序规则**：前台列表查询时，先按 `is_top DESC`（置顶在前），再按 `create_time DESC`（最新在前）排序。
3. **草稿机制**：`status = 0` 为草稿，前台不展示草稿内容，仅管理端可见。
4. **富文本内容**：`content` 字段存储富文本 HTML。管理端编辑时使用富文本编辑器（如 WangEditor），图片通过已有的文件上传接口（`/api/files/upload`）上传后获得 URL，嵌入到 HTML 内容中。前台展示时使用 `v-html` 渲染。

## 6. 业务流程

### 6.1 新增公告流程（ADMIN）

1. 管理员在资讯管理页点击"新增公告"
2. 填写标题、富文本内容（可在编辑器中插入图片），选择是否置顶
3. 选择发布或存为草稿
4. 后端校验登录态与角色（ADMIN）
5. 保存公告记录，返回公告 ID

### 6.2 新增非遗故事流程（ADMIN）

1. 管理员在资讯管理页切换到"非遗故事管理" Tab，点击"新增故事"
2. 填写标题、富文本内容（可在编辑器中插入图片），选择关联非遗项目、是否置顶
3. 选择发布或存为草稿
4. 后端校验登录态与角色（ADMIN）
5. 若关联了非遗项目，校验项目是否存在（不存在则忽略关联）
6. 保存故事记录，返回故事 ID

### 6.3 前台资讯浏览流程

1. 用户点击 Header 导航"资讯"，进入资讯页
2. 默认展示"公告" Tab，显示已发布公告列表（置顶在前）
3. 切换到"非遗故事" Tab，显示已发布故事列表（置顶在前）
4. 点击某条公告/故事，进入详情页查看完整内容

## 7. 安全设计

### 7.1 访问控制

- 管理端接口：仅 `ADMIN` 角色可访问
- 前台展示接口：允许所有登录用户访问

### 7.2 输入验证

- 创建/编辑时：`title`、`content` 非空
- 标题长度限制 200 字符
- 状态值仅允许 0 或 1
- 置顶值仅允许 0 或 1
- 关联非遗项目 ID 校验（如提供则需存在）

## 8. 注意事项

1. **分表设计**：公告与非遗故事虽然字段相似，但分表存储，避免 type 字段混用导致查询复杂和后续扩展困难。
2. **富文本内容**：`content` 字段存储富文本 HTML，管理端使用富文本编辑器（如 WangEditor）编辑，图片通过已有的文件上传接口（`/api/files/upload`）上传后获得 URL 嵌入到 HTML 中。前台展示时使用 `v-html` 渲染。
3. **时间字段**：`create_time/update_time` 由数据库默认值维护。
4. **不使用外键**：非遗故事与非遗项目的关联由业务层保证。
5. **置顶逻辑**：设置置顶时不需要取消其他记录的置顶，允许多条记录同时置顶。排序规则为 `is_top DESC, create_time DESC`。
6. **草稿可见性**：前台查询自动过滤 `status = 0` 的记录，仅管理端可见草稿。
7. **XSS 防护**：前台使用 `v-html` 渲染富文本内容时，需对 HTML 内容进行服务端消毒（sanitize），过滤危险标签和属性（如 `<script>`、`onerror` 等），防止 XSS 攻击。
