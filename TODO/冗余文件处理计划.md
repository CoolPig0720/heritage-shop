2. 不做“可能影响功能”的激进删除：所有删除都必须能解释清楚引用关系，并配套验证步骤。

## 盘点结果与处理建议（按目录）

### 1) frontend/src/views（页面）

**盘点结论**

- “是否冗余”不能只看是否注册路由：有的页面虽然注册了路由，但实际没有任何菜单/按钮会跳转到它，属于“仅 URL 深链可达”，更接近冗余占位页面。
- 因此本次前端页面盘点采用两层检查：
  1. 路由注册：`frontend/src/router/index.js` 是否存在该页面的路由组件引用
  2. 真实可达性：是否存在 UI 入口（Header/Footer 菜单、页面内按钮跳转、列表点击进入等）能到达该路由

**可达性矩阵（按路由）**

**建议动作**

- 对 UI 可达/条件可达页面：不建议删除。
- 对“仅 URL 可达”的页面：优先核实是否真的需要（例如是否计划在商家后台提供“定制订单”入口）。若确认不需要，属于优先清理候选。
- 对“仅为兼容历史链接”的重定向路由：保留路由重定向即可，不需要对应页面文件。

**验证方式**

- 前端构建：`cd frontend` 后执行 `npm run build`
- 手工回归：登录后依次访问主要路径（首页/非遗/智能定制/商品/购物车/订单/管理后台/商家后台）

### 2) frontend/src/api（接口封装）

**盘点结论**

- `src/api` 下各模块（auth/cart/order/payment/product/shop/heritage/aiImage）均存在被页面导入使用的记录，暂未发现“完全未被引用”的 api 文件。

**建议动作**

- 暂不删除 api 文件。
- 若要进一步瘦身：可以在不改功能前提下做“导出粒度收敛”（只导出被用到的方法），但这属于重构，不建议与删除混做一轮。

### 3) frontend/src/components、layouts、stores、utils、styles

**盘点结论**

- Header/Footer 被各 Layout 复用；stores/user 被路由守卫与 Header 使用；utils/theme 与多语言工具被 Header 使用。

**建议动作**

- 暂不删除上述目录内容。

### 4) backend/uploads（运行时上传目录）

**盘点结论**

- `uploads` 目录是运行时依赖路径：文件上传与 AI 图片生成均会写入该目录，并且后端通过 `/uploads/**` 暴露静态资源访问。
- 当前仓库中存在大量样例图片/模型文件，属于运行时产物，容易造成仓库膨胀与“误把样例当数据”的问题。

**建议动作（推荐）**

1. 仅保留目录结构（`uploads/`、`uploads/ai-history-ref/`、`uploads/ai-history-result/`），清空其中的样例文件。
2. 将运行时产物加入忽略规则，避免后续再次被提交（建议在 `.gitignore` 增加 `backend/uploads/` 或更细粒度的忽略条目）。

**风险等级**

- 中：如果你依赖仓库内样例文件做演示/截图，清空后需要重新生成。

**验证方式**

- 启动后端，上传文件与 AI 生成图片流程可用；访问 `/uploads/**` 能正确读取新生成的文件。

### 6) backend/src/main/resources/sql（SQL 脚本）

**建议动作**

- 若后续要精简：可在确认数据库迁移方式后（Flyway/Liquibase/手动执行）再决定是否归档到 TODO 文档或移出仓库。

### 7) TODO/（设计文档与任务清单）

**盘点结论**

- TODO 目录内同时包含“设计方案”和“开发任务清单”，内容可能存在重复，但它们属于管理类资产，是否冗余取决于你是否仍在按这些文档推进。

**建议动作（稳妥顺序）**

1. 先做“标记”：在每份文档开头加一行状态（仍在使用/已过期/待合并），再决定删/留（避免误删仍在用的依据）。
2. 对已过期且不再参考的文档，优先移动到归档目录（例如 TODO/archive）而不是直接删除；确认 1~2 周无人再用后再删。

**风险等级**

- 中：删掉后通常不可逆且影响回溯决策依据。

### 8) 仓库根目录的杂项文件

**盘点结论**

- 目前根目录存在开发手册类文档与脚本文件，是否冗余取决于团队是否仍使用。

**建议动作**

- 暂不删除，先确认是否用于环境搭建/交接。

## 执行顺序（建议）

1. 低风险：删除 `backend/hs_err_pid*.log`，并加入忽略规则
2. 中风险：清空 `backend/uploads` 中样例运行时产物，并加入忽略规则
3. 管理资产：对 TODO 文档做状态标记与归档，再决定删除
4. 最后统一跑一次构建与关键路径回归

## 删除前的统一检查清单

1. 全局搜索该文件名/路径是否被引用（路由、import、配置项、静态资源路径）
2. 前端执行 `npm run build`
3. 后端启动自测关键接口（登录/商品/购物车/订单/上传/AI 生成）
