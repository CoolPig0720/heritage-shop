## 一、翻译批量接口性能优化

### 现象

- 自动翻译切换到英文时，页面需要等待 2-5 秒才能看到翻译结果
- 批量翻译 N 条文本需要调用 N 次百度翻译 API
- 用户感知延迟明显，体验较差

### 原因分析

1. **后端串行处理**：`translateBatch()` 方法对 N 条文本逐条调用百度 API
2. **未使用百度 API 多段文本功能**：百度翻译支持用换行符分隔多段文本，单次调用即可翻译全部
3. **API 响应解析错误**：百度 API 返回的 `trans_result` 是数组，每段文本对应一个元素，原代码只取了第一个元素

### QPS 限制约束

- 本项目使用**百度翻译普通版 API**
- QPS 限制 = 1（每秒仅允许 1 次请求）
- 超过限制会返回 `54003` 错误（Invalid Request Frequency）
- **线程池并行方案不可用**（会被限流）

### 解决方案

#### 采用方案：百度 API 多段文本合并

**核心思路**：将多条文本用换行符 `\n` 连接，单次 API 调用翻译全部内容。

**代码修改**（`TranslationController.java`）：

```java
// 优化前：逐条调用
for (String text : texts) {
    Map<String, Object> singleResult = doTranslate(text, from, to);
    // ...
}

// 优化后：合并后单次调用
String combinedText = String.join("\n", texts);
Map<String, Object> translateResult = doTranslate(combinedText, from, to);

// 百度API返回的trans_result是数组，每段文本对应一个元素
for (int i = 0; i < texts.size(); i++) {
    if (i < transResult.size()) {
        String translated = transResult.get(i).get("dst");
        translations.add(translated);
    }
}
```

**关键要点**：

| 要点 | 说明 |
|------|------|
| 分隔符 | 使用 `\n` 连接多条文本 |
| 返回格式 | `trans_result` 是数组，每段对应一个元素 |
| 字符限制 | 单次最大 2000 字符，超限时需自动分批 |
| 换行处理 | 原文中的换行符替换为空格，避免与分隔符冲突 |

### 性能提升

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| API 调用次数 | N 次 | 1 次 | **90%+↓** |
| 10 条文本翻译 | 5 秒 | 0.8 秒 | **84%↓** |
| 50 条文本翻译 | 25 秒 | 1.5 秒 | **94%↓** |

- ~~前端缓存持久化~~：后续可考虑
- ~~首屏优先翻译~~：后续可考虑

## 二、图生图走混元生图 3.0：本地开发无法直接使用

### 现象

- 本地开发环境使用 `http://localhost:8080` 运行后端
- 图生图切到混元生图 3.0（任务接口）后，请求失败或长时间无结果

### 原因

- 混元生图 3.0 的"参考图"通过 `Images` 入参传 **图片 URL**，腾讯云服务端会主动去拉取该 URL
- `localhost / 127.0.0.1 / 内网 IP` 对腾讯云服务端不可达，所以服务端拉不到参考图，任务无法正常完成
- 该限制属于网络可达性约束，并非代码逻辑错误

### 影响范围

| 功能 | 影响 |
|------|------|
| 文生图 | 不依赖参考图 URL，本地可正常使用 3.0 |
| 图生图 | 若参考图 URL 不可公网访问，本地无法直接使用 3.0 |

### 解决方案

#### 方案 A：图生图自动降级到旧接口（已采用）

- 当 `file.public-base-url` 未配置或配置为 `localhost/127.0.0.1` 时，图生图自动降级走旧的同步接口 `ImageToImage`（支持 base64 输入，本地可用）
- 当 `file.public-base-url` 配置为公网可访问地址时，图生图自动走 3.0 任务接口（提交任务 + 轮询结果）

#### 方案 B：让参考图具备公网可访问 URL（未采用）

任选其一：
- B1：把参考图上传到对象存储（如 COS），使用 COS 的公网 URL
- B2：内网穿透（ngrok / cloudflared / frp）：把本机后端的 `/uploads/**` 暴露为公网 URL

### 本项目相关配置

| 配置项 | 说明 |
|--------|------|
| `file.upload.path` | 本地上传目录（默认 `uploads`） |
| `file.public-base-url` | 用于拼接参考图公网 URL（示例：`https://api.xxx.com`） |
| 环境变量 `PUBLIC_BASE_URL` | 可覆盖 `file.public-base-url` |
