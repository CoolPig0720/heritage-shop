# 问题记录

## 图生图走混元生图 3.0：本地开发无法直接使用

### 现象

- 本地开发环境使用 `http://localhost:8080` 运行后端。
- 图生图切到混元生图 3.0（任务接口）后，请求失败或长时间无结果。

### 原因

- 混元生图 3.0 的“参考图”通过 `Images` 入参传 **图片 URL**，腾讯云服务端会主动去拉取该 URL。
- `localhost / 127.0.0.1 / 内网 IP` 对腾讯云服务端不可达，所以服务端拉不到参考图，任务无法正常完成。
- 该限制属于网络可达性约束，并非代码逻辑错误。

### 影响范围

- 文生图：不依赖参考图 URL，本地可正常使用 3.0。
- 图生图：若参考图 URL 不可公网访问，本地无法直接使用 3.0。

### 解决方案

#### 方案 A：保持本地开发，图生图自动降级到旧接口（推荐先用）

- 当前实现：当 `file.public-base-url` 未配置或配置为 `localhost/127.0.0.1` 时，图生图自动降级走旧的同步接口 `ImageToImage`（支持 base64 输入，本地可用）。
- 当 `file.public-base-url` 配置为公网可访问地址时，图生图自动走 3.0 任务接口（提交任务 + 轮询结果）。

#### 方案 B：让参考图具备公网可访问 URL（本地也能用 3.0）

任选其一：

- B1：把参考图上传到对象存储（如 COS），使用 COS 的公网 URL 作为参考图 URL。
- B2：内网穿透（ngrok / cloudflared / frp）：把本机后端的 `/uploads/**` 暴露为公网 URL，然后将 `PUBLIC_BASE_URL`（或 `file.public-base-url`）设置为该公网域名。

### 本项目相关配置

- `file.upload.path`：本地上传目录（默认 `uploads`）
- `file.public-base-url`：用于拼接参考图公网 URL（示例：`https://api.xxx.com`）
- 环境变量：`PUBLIC_BASE_URL` 可覆盖 `file.public-base-url`
